战斗 AI 的攻击调度：超越功夫圈

个人独立 · 2026.09 · 主要参考：Michael Dawe, "Beyond the Kung-Fu Circle", Game AI Pro Ch.28

攻击调度流程示意

一、问题：群体围攻时如何控制攻击节奏

动作游戏在难度与挑战上有一组固有矛盾。遭遇战（encounter）里常有多个敌人围攻玩家， 这从设计角度往往是需要的——为了拉长战斗时长，或出于叙事需求。 但同时攻击的敌人一多，新手玩家会直接被淹没，所以这类游戏普遍限制敌人一次只能上一个。

朴素解法是"一次只允许一个敌人攻击"。这套做法有个形象的名字：功夫圈（Kung-Fu Circle）—— 取自功夫片里主角被几十个敌人围住、但敌人永远一个一个上的经典场面。

关于「圈」字的来源

原文明确说这个命名取的是那个画面——主角站在中间，敌人围成一圈；不是在说攻击的"循环"。 中文里描述同一机制的现成说法是车轮战。所以更完整的对照是：

说法强调什么
功夫圈（Kung-Fu Circle）源术语，取"敌人围成一圈"的画面意象
车轮战中文现成词，取"轮流上、不一起上"的机制

功夫圈实现简单，在"希望玩家专注单个对手"的游戏里是合理的。但它的限制在快节奏战斗里太严：

  • 战斗节奏被拖慢，玩家缺少爽快感
  • 玩家没有机会使用大范围攻击（AOE, area of effect）——因为敌人从不扎堆

为此需要放宽限制，允许多个敌人同时攻击。但直接改成"允许 2～3 个同时上"是错的—— 它完全不考虑敌人类型差异和攻击强度差异：一个巨魔的冲锋和杂兵的挥剑，显然不该被同等对待。

《Kingdoms of Amalur: Reckoning》给出了一套解决方案。

二、Belgian AI：网格与容量

Reckoning 内部把这套系统叫 Belgian AI——得名于描述算法时画的华夫饼（waffle）草图： 网格槽位看起来像格子松饼。

核心思想：每个角色身上随身携带一个网格（grid）。

  • 网格以角色为中心、与世界坐标轴对齐（world-space aligned，不随角色朝向旋转）
  • 共 8 个空槽位（slot），像井字棋（tic-tac-toe）棋盘，角色位于中心
  • 网格存储两个变量：网格容量（grid capacity）与攻击容量（attack capacity）
    • 网格容量限制同时能攻击的角色数量
    • 攻击容量限制这些角色能使用的攻击数量与类型

每个生物（creature）有一个 网格权重（grid weight），即它占用他人网格槽位的成本； 每个攻击有一个 攻击权重（attack weight）。两条规则：

正在攻击某角色的所有生物，其网格权重总和必须小于该角色的网格容量；

正在对该角色使用的所有攻击，其攻击权重总和必须小于该角色的攻击容量。

2.1 运转实例

设玩家的网格容量为 12：

步骤事件权重剩余网格容量
1士兵请求攻击，权重 4412 − 4 = 8
2巨魔请求攻击，权重 888 − 8 = 0
3第二名士兵请求，权重 444 > 0，拒绝，只能在网格外等待

继续看攻击容量的作用。设玩家攻击容量为 10：

步骤事件权重剩余攻击容量
1巨魔从「冲锋(6)」与「挥棒(4)」中选择冲锋610 − 6 = 4
2士兵有「突刺(5)」与「剑挥(3)」；突刺 5 > 4 用不了——
3士兵改用剑挥34 − 3 = 1

注意第 2 步：士兵不是被禁止攻击，而是被限制只能用"便宜"的攻击。 这是这套系统区别于简单计数的关键——它压的是攻击强度，不只是数量。

2.2 舞台管理器（The Stage Manager）

个体生物不做任何空间推理（spatial reasoning）。 所有定位与槽位分配由一个集中式 AI 负责，称为舞台管理器（stage manager）。流程：

  1. 士兵察觉玩家，向舞台管理器注册攻击请求并等待
  2. 舞台管理器在下一帧处理请求，比对士兵网格权重与玩家当前剩余网格容量
  3. 通过则分配最近的可用槽位，并扣减剩余容量
  4. 士兵获得接近并攻击的许可（permission）

集中化是这个设计最重要的工程决策，第六节会看到它带来的全部好处。

三、三层同心圆

网格槽位虽然叫"网格"，但本质上定义的是与玩家等距的若干位置，围成一个圆。 Reckoning 进一步把它分成内外两层，加上圈外，形成三个半径：

区域名称谁在这里
内圈攻击圈（attack circle）只有已获准使用某个具体攻击的生物
外圈接近圈（approach circle）已通过网格容量检查、获准接近，但还没获准具体攻击
圈外—未通过网格容量检查，等待机会

攻击圈的半径由近战攻击（melee attack）的最小/最大距离定义。

这个分层对玩家体验的价值：玩家一眼就能判断谁是当前的直接威胁。这比任何 UI 提示都有效。

四、行为集成（Behavior Integration）

为配合网格系统，Reckoning 的生物共享一组通用行为，同时提高了行为复用率（behavior reuse）—— 任何能近战攻击的生物都共用这套行为集。四条规则：

  1. 已进入外圈但无攻击许可的生物，必须尽快离开圈。 价值有二：让玩家清楚哪些敌人在攻击；防止怪物在真正攻击时互相挡路。
  2. 圈外等待者会被分配一个未被占用的槽位位置，并站到该槽位前方（即使没有攻击许可）。 结果是自然形成包抄（flanking）——而且任何生物都不需要知道其他生物的存在。 这是整个设计里最优雅的一处：包抄不需要"包抄行为"，它是定位规则的副产物。
  3. 攻击发起后立即把槽位交还（relinquish）舞台管理器。 舞台管理器据此排队轮换，保证生物不断进出近战范围，单个生物无法垄断（monopolize）攻击机会。
  4. 生物数量少时，交出槽位的生物可以立刻被重新分配，不产生空窗。

五、难度缩放（Difficulty Scaling）

这是这套系统最实用的性质：难度完全由两个数字控制。

调整项效果
提高网格容量更多生物能围住玩家
提高攻击容量更多生物能同时攻击，且能用更强的攻击

关键在于：完全不用改动每个生物精心平衡过的个体权重配置。 策划只需调整玩家侧的两个容量值，就能为多个难度等级生成不同的遭遇战，而所有生物的数据保持不变。

六、工程细节：槽位动态重分配

网格是世界对齐的，随玩家移动。这带来一个问题： 玩家翻滚躲开攻击后，生物此前被分配的槽位可能不再是最优的。

解法：舞台管理器拥有槽位的完全分配权。

  • 生物从不记忆自己的槽位，每帧向舞台管理器查询当前分配
  • 空网格时，优先分配给距离最近的生物
  • 已占用时，舞台管理器可以重新洗牌——把许可从 A 转给 B（steal 机制）

一个具体场景：玩家原被巨魔和士兵围攻，第二名士兵在圈外等待。 若玩家突然朝第二名士兵移动，舞台管理器应当把攻击许可从第一名士兵转移给第二名。

实际调参的取舍：倾向于不动已有许可的生物，除非出现"获准者已在攻击网格外、 而某个未获准者已进入网格范围"的情况。重分配的目标是最小化所有生物到达目标位置的总行进时间。

槽位锁定（lock）：正在发起攻击的生物会锁定自己的分配， 防止攻击过程中被抢走槽位而意外冲爆玩家的攻击容量。

分配算法伪代码（pseudocode）：

Attacking list = 所有正在攻击的生物

For each creature in Attacking list:
    slot = 为 creature 查找最近的槽位
    If slot 已锁定:
        continue
    将 slot 分配给 creature
    从 Attacking list 移除 creature
    If slot 原本已有归属:
        解除该生物对 slot 的占用

七、工程细节：攻击种类限制

攻击容量只管总量，不管种类。在高难度下（攻击容量被调高）， 或者遭遇战里同种生物特别多时，会出现大量同类型攻击同时释放的问题——比如一堆范围攻击同时砸下来。

Reckoning 的补充手段是三层冷却（cooldown）：

层级作用范围
个体级（individual）单个生物的特定攻击冷却
生物种类级（creature-wide）同一类型生物共享的攻击冷却
全局级（global）整场战斗范围内该攻击的冷却

这对最高难度下的平衡作用极大——即使攻击容量被提高， 也能阻止特定敌人同时释放过多 AOE 攻击。

八、设计要点总结

  1. 难度是可缩放的数据，不是写死的行为。两个容量值 + 每个生物一组权重，覆盖全部难度曲线
  2. 权重让"强度"参与调度，而非只是"数量"。判定的是加权总量，所以强敌天然挤占弱敌的机会，不需要额外规则
  3. 定位逻辑集中化是这套算法的真正强项。个体生物只负责"执行我拿到的许可"，不思考全局
  4. 包抄是规则副产物。等待者被分配到空缺槽位前方——没有任何"包抄"代码，行为自然涌现（emergent behavior）
  5. 攻击完立即交还槽位，保证轮换公平，防止单个敌人垄断输出窗口

原作者在结论中明确指出：这套算法可简单与影响力图（influence map）技术结合， 让角色更自然地避让与在世界中移动；网格槽位的概念也可与其它战术技术自由组合。 真正的价值不在实现难度，而在定位逻辑集中化带来的灵活度。

九、与 UE5 的对应实现

这套系统的三层结构在 UE5 里都有落点：

本文机制UE5 对应
舞台管理器 一个独立的 Manager Actor（或 GameMode 上的子系统），持有网格与容量状态
槽位位置计算 EQS（Environment Query System，环境查询系统）：以玩家为中心，查询等距可用位点
个体行为（离开外圈、站到槽位前） 行为树（Behavior Tree）里的 Move To 任务，条件由黑板键（Blackboard key）驱动
攻击请求与许可 黑板键（是否有攻击许可）或 Gameplay Tag
攻击权重与冷却 Gameplay Ability System（GAS）的 Cost 与 Cooldown

一个最小实现路径：先在 BT 里给敌人加一个"请求攻击许可"的任务节点，向 Manager 注册； Manager 每帧统一分配并在黑板上写回许可与目标槽位；敌人据此执行 Move To 或攻击。

关键是不要让敌人在自己的行为树里做全局空间判断——那是这套设计要避免的头号错误。
